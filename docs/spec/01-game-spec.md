## 3. 一局流程（狀態機）
```
TITLE → OPENING → [YEAR ×7: NEWS → SETUP → WALL → (PUBLISH) → REACTION → (LIFE?) → BABY?] → FINAL_WALL → REUNION → LANTERN（玩家寫老顏的燈，§10）→ VERDICT → 私訊 → SOURCES → END
```
- OPENING（C9、D4）：①2018 群組：同學恭喜老顏找到好工作（3 則，帶身分）。②辦公大樓前六人背對鏡頭高舉右手的合照（全彩），一行字「約好八年後再來這裡拍一張」。③「上班」按鈕。
- NEWS（A6）：新聞剪報一行，真實數字。
- SETUP（C12、A7）：1–2 則群組訊息，由當年相關的同學說出處境做鋪陳（不表態選邊），帶身分標籤。
- WALL（C1、C2）：全寬大圖左右半；買單者第一次出現時角落有一句私事；第一面牆有操作提示文字。點一半＝選中（彩色＋標語，10-28 改為只用點選），按「發布」＝確定。不能重選（F1）。
- REACTION：主管便利貼 1 則＋群組 1 則（首則必為被裁者；選右時為受惠者淡淡一句）（D5）。
- LIFE（C4）：只在選右後出現；第 1–3 次各一個新物件（未讀訊息→回診單過期→相框只剩一隻手）；第 4 次起不再新增物件，改為相框再褪一階＋一行字。
- BABY（C10）：每局隨機 2–6 則「本班第 N 位小朋友」動態卡（同學抱嬰兒照＋一句恭喜），插在年與年之間；約每 2–3 年一則；與選擇無關（C7）。總數 = 結尾阿芳說的數字。
- 大事件洗版（D6）：2021 停課與 2026 最後一張，SETUP 改為 4–5 則快速連發。
- FINAL_WALL（C6）：2026 主管「這張妳自己裁」。左＝佩珊請半天陪孩子；右＝老顏與兩疊卷宗（右半畫面依選右次數 0／1–2／3+ 三版）。
- REUNION（C3、C9、G2）：同一棟辦公大樓前，六人轉過身來的合照；被裁過的同學依序起身走出，留下虛線空位；每人說一句代價（數字只在這裡出現），可追問（§6）。老顏若最後一張裁掉自己：她是拿相機的人，走不了，黑白留在畫面。
- VERDICT（G4）：一行斷語標題（例：「妳的宣傳照很好看，合照只剩三個人」），由 AI 依路徑生成；離線時用預寫 8 句。
- SOURCES（A6、K1–K9）：一屏可捲動的出處頁，規格見 §11（S7，2026-10-28 取代舊的單頁出處列表；舊列表只在 data.js 缺 sources 時當退路）。
- END：阿芳總結（C8 原句）→「再拍一次」。

## 5. 狀態與規則
- `gone[]`：被裁過的同學（含節點紀錄 `cutIn[name]=[nodes]`）。
- `self`：選右次數（0–6）。生活物件索引 = min(self,3)；相框褪色階 = max(0,self-3)。
- `laoyanGray`：最後一張選左。
- 主管耐心：不設數值、不調職（prop6 規則廢止，避免第二套系統，C14）。
- 平衡檢查（A2）：16 種主幹組合中，不得有「無人走出且老顏 0 格」的路徑；全右路徑老顏結局必須最重；全左路徑走出人數最多。驗收見 §8。

## 6. AI 規格（G1–G4、G6）
- 角色：Muse Spark 1.3（standard，非 contributor，因內容含玩家輸入）。
- 呼叫點 1：REUNION 每位走出的同學的代價句（輸入：角色卡、被裁年份與新聞、老顏 self、本局其他人去留）。
- 呼叫點 2：追問。玩家可點 3 個建議問題或自由輸入（≤40 字），每人最多 3 問；角色內回答；離題（例：費馬大定理）以角色口吻帶回自身處境（G3）；不得說教、不得評價政府真實人物。
- 呼叫點 3：VERDICT 斷語（≤20 字）。
- 架構：靜態頁→中繼站（只接受本遊戲 origin、每 IP 每分鐘 10 次、單局 12 次上限、記帳）→api.meta.ai。【待決 Q3】中繼站平台需使用者帳號（建議 Cloudflare Workers 免費方案）。
- 離線備援：中繼站失敗或逾時 4 秒，改用 data.js 預生成句（現已有 14 組＋8 結局＋固定 3 題），畫面不顯示錯誤。
- 揭示：SOURCES 頁一行「同學會台詞由 Meta Muse Spark 依妳這局的選擇即時生成」。
- 為何不可拿掉（G1 論述）：同學說的是「妳這局」對他做了什麼，路徑組合 × 追問內容無法預寫窮盡。

## 7. 資料與檔案
- `index.html`：引擎（不含文案）。
- `data/zh.js`、`data/en.js`：全部文案，每格標 `src: user|ai-draft`（E1：使用者覆寫後改 user）。
- `img/<pack>/…`：資產包（F6），`pack` 切換一次換全套；預設 pack 由使用者定。
- `tools/`：生成腳本；`proxy/`：中繼站原始碼（不含金鑰）。

## 8. 驗收測試（每次推版必跑，H5）
1. 冒煙 200 局：100% 到結尾、0 JS error、每位走出者都有代價句、老顏結局句存在且只一句。
2. 路徑窮舉（7 節點共 2^7）：輸出走出人數／self 分佈表，檢查 §5 平衡規則。
3. 文案 lint：所有對老顏的第二人稱為「妳」；每則群組訊息有身分標籤；同牆左右不同人；字數上限（群組 24、私事 18、標語 16、代價 45）。
4. 實機截圖自玩：全左、全右、交錯三條，逐一對照 00 表打勾。
5. 英文模式同上 1、4。

## §10 結局天燈拍（L1，2026-10-28 17:03 使用者核可；取代系統自動寫的老顏燈）
- 位置：2026 平溪同學會，同學的燈依序亮完後，輪到老顏的燈時，願望卡變成輸入框（placeholder「寫在老顏的燈上」、「放！」鍵、字數計）。不顯示出處、不接 AI、不放金鑰，全部本機運行。
- 字數：12 字內，可中英。計法：中日韓字 1、其他字元 0.5，上限 12（等於 12 個中文字或 24 個英數字）；輸入法組字中不截斷，組字結束才截。
- 空白送出不阻擋：燈上不寫字（原本空白燈版），對照格顯示「（什麼都沒寫）」。
- 髒話：燈上與對照格打碼成「▇」（每字一格），回應不引用燈上的字。
- 過場固定 5 秒（點擊不能跳過，播放時鎖翻頁）：0–0.8 秒字寫上燈（中文直書、純英數橫書）→0.8–1.4 點火變亮→1.4–3.6 與同學的燈一起升空，退群同學的燈是暗的→3.6–5 畫面變手機「我們這一班（在群人數）」，佩珊傳來一張燈的照片（照片裡退群者的燈也是暗的）。
- 5 秒時：一位還在群組的同學回一句（規則見下），接著片尾一格對照：「燈上：〈玩家字〉／海報上：〈玩家 2026 年實際留下的那張海報主標〉」（選上＝佩珊那張「按日請育嬰假」；選下＝老顏那張「謝謝每一位補位的你」；英文版用英文主標）。標籤只寫「燈上／海報上」，不加評語。之後「點一下繼續」→ 判詞頁 → 結局私訊 → 出處頁（S7 新版見 §11）。
- 回應規則（依序比對，第一個命中者用；回應者取該類順序中第一位仍在群組的人；佩珊所有路線都不退群，保證有人回；家豪有 16/128 條路線會退群，所以家豪類都有佩珊替代句）：

  2. 點名一位還在群組的同學（中文名或英文名，取燈上最先出現且仍在群組者）：由被點名的本人回
  3. 5/24、她、結婚、戒指、約會、伴侶…：佩珊
  4. 回診、醫生、身體、健康…：宜君→佩珊
  5. 睡、休息、累、放假…：家豪→佩珊
  6. 對不起、原諒、抱歉、欠…：志豪→家豪→佩珊
  7. 點名已退群的同學、大家、群組、回來…：佩珊
  8. 辭職、升、科長、考績、海報…：家豪→佩珊
  9. 其他：佩珊
- 台詞與英文關鍵字見 tools/content_zh.py `LANTERN`；data.js `lantern`。
- 「2027 換妳寫」不放進正式遊戲（使用者 2026-10-28）。

## §11 出處頁新版（S7，2026-10-28 18:49 使用者決定；V=20261028e）
- 資料：tools/sources_zh.py（出處庫 22 張卡 64 句、猜猜看、建議問題、公開進度、介面字）＋ tools/sources_en.json（英文，Muse 初譯、Hark 審）＋ tools/sources_rec.json（錄製答案）→ build_data.py → DATA.sources。出處庫每句都開過原文核對；只許改語序，不許加內容。
- 位置：結局私訊之後的最後一屏（class `sp`）。整屏內部可捲動（`.spb`），在這一屏滾輪、方向鍵、上下滑都只捲動，不翻回上一屏。
- 順序：
  1. 標題「出處」＋一句導言＋F00 虛構聲明（老顏和五位同學、群組、私訊是虛構；政策標語金額有出處；海報被拿去堵人是戲劇化）。
  2. 猜猜看：從本局走過的年份挑 3 題，盡量真的／改編／虛構各一（虛構題只有走過 2025 上半〔y2025e〕才有）。題目必須是遊戲裡一定出現過的原句（主管便條、群組 setup、海報主標或角落字），play.py 會比對。按任一選項＝鎖定，正解變綠、選錯的劃線，翻出判定＋說明＋出處原句＋連結。
  3. 還想查什麼？：8 個建議問題（chips）。點一下＝顯示錄好的答案：固定開頭（「出處庫找到 N 句：」／「這題問的是遊戲角色。出處庫的說明：」／「出處庫裡沒有這題的資料，所以沒有答案。」）＋原句＋連結＋灰字「Meta Muse 從 64 句已查證出處挑出 N 句（預先錄製）」。答案是 Muse 只挑句子編號（tools/sources_muse.py record，每題跑 3 次、人工挑 1 次，理由記在 sources_rec.json 的 why）。預設不顯示輸入框。
  4. 這七年留下的海報：本局實際留下的 7 張（年份＋主標＋文宣／現場標籤），點開＝那年的出處卡（NODE_CARD；2026 只放按日育嬰那張，其餘在第 5 段）。
  5. 截至 2026 年 10 月的公開進度：5 則，標籤只用 已上路／已提出／規劃中／審查中／協商中＋原句＋連結。
  6. 片尾字幕（原 credit＋「查證：Meta Muse 只從本頁出處庫挑句子，不自己寫事實」）＋「再拍一次」。
- 即時開關：index.html `const ASK_URL=window.BB_ASK_URL||''`。設成 Worker 網址後才顯示輸入框（≤40 字）；建議問題仍用錄好的答案。自由輸入先在前端擋明顯的髒話與「忽略…指示／ignore previous」（其餘交給 Muse 分類 abuse；→「這題不在查證範圍。」），再 POST {q} 給 Worker，4 秒逾時或失敗＝「離線查證模式：自由提問要等連線，建議問題不受影響。」Worker 回的句子編號只顯示出處庫裡存在的（前端與 Worker 都過濾），最多 3 句。灰字改「（即時，N 秒）」。
- Worker（tools/ask_worker.js，由 sources_muse.py worker 產生）：只收遊戲頁來源、每 IP 每日 10 次、總花費到 US$5 熔斷（KV 計數），不存玩家原文；金鑰放 Worker secret META_KEY。部署步驟 docs/ask-worker.md。
- 退路：DATA.sources 不存在（CDN 上 data.js 比 index.html 舊）→ 先自動重載一次，仍沒有就顯示舊的單頁出處列表。
- 驗收（tools/play.py 自動）：F00 在最上；每題猜猜看三個選項都點過且判定正確；8 個建議問題都點過，句數＝錄製、灰字含「預先錄製」、連結 https＋另開新分頁＋沒被蓋住；留下的海報＝本局路徑且都能展開；進度標籤正確且無「跳票、破局、卡著、還沒上路、仍在等」；無橫向溢出、無 {x}／undefined；斷網（context offline）後建議問題照常；`live=mock|down|slow` 測即時開關。
